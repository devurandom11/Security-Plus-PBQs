Scenario

Briefing and access policy for the Northwind Campus perimeter firewall deployment.

Northwind Campus is replacing an aging perimeter firewall that had accumulated years of ad hoc exceptions. The replacement is a stateful appliance being brought up with an empty rule base, so the access policy is written from scratch rather than migrated.

Two zones sit behind the firewall. The screened subnet, 172.22.40.0/24, holds the customer portal, the inventory host, the resolver, and the outbound mail relay. Campus workstations sit on the LAN, 10.44.18.0/24, and reach the screened subnet only through the firewall. Because the appliance is stateful, you write a rule only for the direction a session opens in; return traffic is allowed automatically and no rule pairs are needed.

Access policy

  1. Allow HTTP and HTTPS from any external address to the customer portal.
  2. Allow remote secure terminal administration from the designated help desk workstation only to the inventory host.
  3. Allow name-resolution queries from any campus device to the resolver.
  4. Allow STARTTLS mail submission from the campus network to the outbound mail relay.
  5. Deny all other traffic by default.

This is the whole of the policy. Anything it does not name must fall through to the default deny at the bottom of the list.

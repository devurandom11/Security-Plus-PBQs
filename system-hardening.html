Scenario

Briefing and hardening requirements for the Northwind server hardening exercise.

NW-APP-12 is a Linux application server that runs the Northwind Field Services API. nginx publishes the API over TLS, PostgreSQL runs on the same host, and a media share is mounted over NFSv4. The host failed its baseline audit, and you are writing the remediation plan. Pick the one action that closes each finding without breaking the application.

Requirements

  • SSH from the jump host at 10.42.7.19 is the only administrative path; it must keep working. Every administrator already has an SSH key.
  • The monitoring platform at 10.42.7.18 must keep polling the admin console on port 9443. Both it and the jump host are in the management subnet 10.42.7.0/24.
  • The NFSv4 media mount must keep working. The rpcbind package is a dependency of nfs-common, but the rpcbind daemon is not used by NFSv4.
  • The database is used only by the API process on the same host.
  • Files holding secrets are readable only by root and the service account that needs them, and never writable by anyone else.
  • Members of nwdeploy still need sudo to restart the API service during deployments. Privilege elevation is limited to named commands.
  • Security updates are applied within 14 days of release, without manual intervention.
